## 1. Data Description

This research uses the Elliptic Bitcoin Dataset, a publicly available graph of Bitcoin blockchain transactions collected and released by Elliptic, a blockchain analytics company. The dataset consists of 203,769 nodes representing individual Bitcoin transactions, connected by 234,355 directed edges representing payment flows between them. Each node carries 166 anonymized features: 93 local features describing properties of the transaction itself (such as timestamp and aggregated amounts) and 72 aggregated features derived from one-hop neighbors in the graph. The dataset spans 49 discrete timesteps, making it a temporal graph. Of the total nodes, 46,564 are labeled: 4,545 as illicit (associated with scams, ransomware, darknet markets, and similar entities) and 42,019 as licit. The remaining 157,205 nodes are unlabeled.

The dataset is distributed in three CSV files: elliptic_txs_features.csv (node features), elliptic_txs_edgelist.csv (graph structure), and elliptic_txs_classes.csv (node labels). The total size is approximately 146 MB. Data was originally generated by Elliptic from the public Bitcoin blockchain and pre-processed to extract features and assign labels based on known illicit and licit entities. The dataset is accessed via Kaggle under its original license.

## 3. Anonymization strategy

Nature of the data. This research uses exclusively the Elliptic Bitcoin Dataset, a publicly released dataset in which anonymization was applied by Elliptic prior to publication. No real personal data, transaction identifiers, wallet addresses, or entity names are present in the dataset. All 166 node features are anonymized and intentionally opaque — feature names were withheld by design, not by omission. This anonymization at source is the reason the dataset exists as a public research artifact: without it, publication would have been legally and ethically impossible.

Why traditional anonymization techniques do not apply. K-anonymity, l-diversity, and t-closeness are table-based techniques designed to protect rows of personal data before publication. They are not applicable here for two reasons. First, the dataset contains no personal data — there are no quasi-identifiers to generalize and no sensitive attributes belonging to natural persons. Second, the data is a graph: the unit of analysis is a transaction node whose most identifying property is its topological position in the network, not a demographic column. Table-based anonymization has no meaningful analogue for graph-structured data of this kind.

Published artifacts and their privacy implications. Four artifacts will be published alongside this thesis: (1) source code, (2) trained GNN model weights, (3) aggregated performance metrics (F1, precision, recall, AUC-ROC), and (4) dataset statistics (class distribution, feature summary statistics). Because the underlying data contains no personal information, none of these artifacts carries membership inference risk with respect to natural persons. Model weights are published to ensure full reproducibility of the reported results.

Differential privacy — scope and justification. Differential privacy (DP) would be required if this research queried or published statistics derived from personally identifiable transaction data. As that condition does not hold for the Elliptic dataset, formal DP mechanisms are not applied in this work. However, the thesis framework explicitly recommends DP — with a declared epsilon and sensitivity appropriate to the query type — for any deployment of GML-based AML systems over real financial intelligence data. This represents a deliberate design decision in the framework artifact, not a limitation of the current validation instance.

Utility-privacy trade-off statement. No utility was sacrificed in the anonymization of the analytical dataset, as anonymization was performed upstream by Elliptic. The trade-off acknowledged in this research is of a different nature: the 166 opaque features constrain interpretability of the model, as feature importance cannot be mapped to domain-meaningful variables. This is documented as a limitation in the thesis.
